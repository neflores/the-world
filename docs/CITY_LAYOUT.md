# Условная планировка города

`WorldCity.latitude/longitude` используются только в региональной карте.
Адрес физического клуба обязателен, но не преобразуется в пиксельную позицию.
Пользователь/host выбирает `CityDistrict`: север, юг, восток, запад, промежуточные
направления или центр. Автоматического геокодирования и GPS нет.

Ключ положения — `(cityId, district, plot)`. Это логическая метаинформация
проекции, а не координаты человека или помещения. `id` места — постоянный ID
организации/профессионального профиля; порядок массива не влияет на положение.

В одном районе сцены шесть читаемых мест (в центре два). При росте количества
появляется следующий квартал (`neighborhood`), а существующие здания остаются
на месте. Все клубы доступны в списке; выбор сам открывает правильный квартал.
Это ограничение плотности одного экрана, а не лимит числа организаций.
Центральная площадь, избранное, портал и ремесленный район сохраняют позиции.

Host должен сохранять назначенный `plot`, не пересчитывая его из текущего
рейтинга, порядка ответа API или избранного. Дублированные ID/места, неизвестные
города и физические клубы без адреса отклоняются конструктором `WorldSnapshot`.
При переносе клуба в другую часть города host явно назначает новое место.

В Simulation очередной клуб получает следующий номер в своём направлении.
Номер сохраняется вместе с ID и оформлением. Запись проходит перед публикацией
нового состояния; неуспешная запись оставляет старую проекцию.

Изображения, NPC и hit targets находятся внутри одного `InteractiveViewer`.
Поэтому перемещение и масштаб камеры применяются к ним вместе.
NPC используют отдельные коридоры `CityLayout.walkRoutes`; клиент вычисляет
движение самостоятельно, серверу не требуются экранные координаты людей.
