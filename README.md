# World · 0.2

Общий Flutter-модуль для живой вкладки World и отдельный Windows Playground.
Региональная карта сохраняет географию Израиля. Города — вымышленные рисованные
социальные хабы; реальные улицы и координаты клубов в них не копируются.

## Запуск

Нужен Flutter stable с Dart ≥ 3.12.2. Проверено локально на Flutter 3.47.4 / Windows.

```powershell
flutter pub get
flutter analyze
flutter test
cd example
flutter run -d windows
```

Для быстрого запуска без режима отладки:

```powershell
cd example
flutter build windows --release
.\build\windows\x64\runner\Release\world_playground.exe
```

На исходной машине `. .\tools\dev-shell.ps1` подхватывает ранее установленные SDK.
Docker, Fluxer и внешняя генерация изображений для запуска Playground не нужны.
Карты и рисунки включены в пакет, загрузки тайлов во время работы нет.
В `example` подготовлены Windows, Android и web-оболочки. Нативные сборки для
iOS/macOS/Linux в этом репозитории пока не проверены.

## Что можно попробовать

- Выбрать город на карте или в списке, приблизить сцену и открыть здание.
- Пройти в главный зал: вывеска, две разные доски, столы открытых наборов.
- Добавить клуб: имя, реальный адрес, город, сторона города, внешний вид.
- Закрепить место в избранном, изменить оформление и увидеть тот же рисунок на карте.
- Открыть карточку гуляющего персонажа, изменить свой социальный статус.
- Включить Quiet Mode или обычный список. Системный Reduced Motion также учитывается.

Все исходные клубы, персонажи и игры помечены как демонстрационные.
Добавленные клубы, избранное, оформление и статус сохраняются **только локально**
в Playground через `SharedPreferencesAsync`. Это не регистрация организации
в AltarApps и не гарантированное серверное хранилище.
При ошибке чтения сохранение не перезаписывается; при ошибке записи действие
не применяется к текущему состоянию.

## Подключение к основному приложению

```dart
import 'package:world/world.dart';

WorldView(
  source: hostWorldDataSource,
  onIntent: hostWorldIntentHandler,
  canCreateClub: permissions.canCreateClub,
  canEditAppearance: (location) => permissions.canEdit(location.id),
)
```

`WorldDataSource.watch()` отдаёт исходный `WorldSnapshot` и дальнейшие полные
замены состояния одним упорядоченным потоком. Host преобразует собственные DTO,
проверяет права, выполняет записи и возвращает обновлённую проекцию.
World отправляет типизированные намерения (`CreateWorldClub`,
`OpenWorldDestination`, `ApplyWorldAppearance`, `SetWorldStatus`, `SetWorldFavorite`).
У него нет своего логина, HTTP-клиента, Fluxer-токена, платежей или глобального роутера.

Simulation подключается явно через `package:world/world_simulation.dart`.
Production не переключается на фиктивные данные при ошибке сети.
Для ClubManager/MasterHub экспортированы `WorldAppearancePreview` и
`WorldAppearanceEditor`: рисунок здания создаётся той же функцией, что и на карте.

## Структура

| Каталог | Ответственность |
| --- | --- |
| `lib/src/model` | Идентичность, города, клубы, внешний вид, присутствие, наборы |
| `lib/src/data` | Контракт источника проекций |
| `lib/src/interaction` | Типизированные действия наружу |
| `lib/src/layout` | Географическая проекция региона и условная планировка города |
| `lib/src/renderer` | Изображения, сцены, единый рендер внешнего вида, NPC |
| `lib/src/runtime` | Подписка на данные, маршруты движения |
| `lib/src/widgets` | Отдельные формы, карточки, карта, список, зал, редактор |
| `lib/src/simulation` | Отдельный источник демонстрационных данных |
| `example/lib` | Локальное сохранение и обработка действий Playground |

Файлы связаны обычными импортами. Общих `part`-монолитов нет.
Canvas используется для сцены, обычные Flutter widgets — для интерфейса.
Неиспользуемые зависимости Flame/flutter_map удалены из пакета; переход на Flame
не требуется для подключения к Flutter-приложению и не меняет публичные контракты.
